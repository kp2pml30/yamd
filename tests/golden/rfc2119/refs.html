A conforming server MUST validate the token before use, and it SHOULD NOT write the raw token to any log. Caching is OPTIONAL; an implementation MAY skip it. Every field marked REQUIRED is still MUST — the two spellings share one requirement level.

MAY
Truly optional: an implementation may choose to include the item because a particular market or situation calls for it, or to omit it; interoperating peers must handle both. [1][2]
MUST
An absolute requirement of the specification. [1][2][3]
MUST NOT
An absolute prohibition of the specification.
SHOULD
Recommended: there may exist valid reasons in particular circumstances to ignore it, but the full implications must be understood and carefully weighed first.
SHOULD NOT
Not recommended: there may exist valid reasons in particular circumstances when the behavior is acceptable or even useful, but the full implications should be understood and the case weighed before choosing it. [1]
